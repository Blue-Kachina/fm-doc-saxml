# Changelog

## Unreleased

### Added

- HTML viewer: a **layout preview**. Each layout is drawn as in FileMaker's Layout mode: parts as bands, every object at its position, in paint order. It shows above the layout page's Markdown (folded on phones) and on a full page, `#/layout?doc=<layout docId>&file=<file>`. Search the layout (labels, fields, names, scripts, tooltips) with matches outlined and stepped through; click a point for the objects under it, front to back; pick each tab control's tab, open popovers, hide objects with a hide condition; badges count objects outside the layout, tiny ones and exact duplicates. Deep links take `&select=`, `&highlight=` and `&q=`. Layout object pages, field pages and layout objects in the `--webmcp` results view link to it ("Show on layout"; in a multi-file build a field's page also lists the other files' layouts that show it). Portals, popovers and other containers aren't labelled with their object names (FileMaker doesn't show them); *Wireframe* shows the name as a small caption in the corner. On by default with `--html` and `--webmcp`; `--no-layout-preview` leaves it out. It adds `_viewer/layout-preview.js` and one small script per layout under `_viewer/data/<file>/layouts/` (about 200 KB for a 29-layout, 1,300-object solution). The Markdown doesn't change. See docs/html-viewer.md, "Layout preview".
- WebMCP layout tools, built on the layout preview's data: `locate_layout_object` ("where is this field / text / script button shown?", on one layout or all; `Table::Field` is tried as the field's docId first, so objects showing it through any table occurrence are found, and a field of another file in a multi-file build is found on the layouts that show it), `objects_at` (hit test at a point or in a rectangle, front to back), `layout_problems` (objects outside the layout, tiny ones and exact duplicates, as rows), and on a layout page (or its full-page preview) `show_on_this_layout`, which highlights matches on the preview. Each object comes with absolute `bounds` (points from the layout's top left), `part`, `shownIn` (tab, slide panel or popover, with the tab's label), `visibleAtOpen`, its z-order, a position in words ("Body, top right, inside the 'Devis' tab") and a `previewUrl`. The results view links each layout's matches to the preview, highlighted. They work by URL (`#/results?q=…&format=json`), are in the `#/agents` guide and `llms.txt`, and exist only when the preview does. For scripts without WebMCP (preview on, `--webmcp` or not): `FMDocs.preview.open(layout, {highlight, select, q})`, `FMDocs.preview.highlight(ids)` and `FMDocs.preview.clear()`. `list_objects_on_this_layout` now points at `layout_problems` for objects outside the layout instead of saying they aren't detected. `get_current_page` says which layout a preview on screen shows and what is selected.
- Layout preview: **theme styles**. The preview now draws each object and part with its theme's normal-state look: background and text colours, borders and corner radii, fonts, text alignment and padding, worked out at build time from the theme's CSS, the object's named style and its local CSS (`analyze/layout_css.py`). A *Styled* / *Wireframe* switch on the preview picks the look (Styled by default; the choice is remembered in the browser). A new badge counts objects hidden under an opaque object in front of them, and `layout_problems` has a matching `covered` kind (with `coveredBy`); the layout tools also return each object's `style`. Styles are read from the scrubbed `raw/` XML, so a build with `--no-raw-xml`, or a `render` from `model.json`, is wireframe only. Adds about 80 KB to `_viewer/data` for a 29-layout, 1,300-object solution.
- Layout preview: **icons and images**. Button and popover button icons are drawn in place (icon only, or beside, above or below the label, at their size), glyph icons in the theme's icon colour (*Styled*) or the kind's colour (*Wireframe*). SVG button icons are included by default; a new `--layout-images` flag on `build` also includes pictures (PNG, JPEG, GIF) and SVG graphics, which can show logos or client artwork the scrubber can't check. Each image is written once per file under `_viewer/data/<file>/library/`, loaded when a layout using it is shown; images over 256 KB, PDFs and other kinds a browser can't show are skipped, and the build prints the counts. SVGs are sanitized (no scripts, animation, event attributes, outside links or CSS imports, metadata) and shown only as images. Without `--layout-images`, `raw/layouts.json` also leaves out the pictures stored on layout objects, except SVG button icons. Both export forms are read: the `<LibraryCatalog>` with references by key (FileMaker 26) and icons stored on the object (FileMaker 22). The click details and the layout tools name each object's `icon` / `image` (and why one wasn't included), and styles gain `icon-color`. The coverage report counts `LibraryCatalog` and a graphic's picture as read. About 66 KB more in `_viewer/data` for the 29-layout solution (52 icons).

- Layouts and scripts say which folders they are in. `entities.json` has `folderPathParts` on each (one item per folder, outermost first, `[]` at the top level) next to `folderPath`, which joins them with `/` and can't tell a folder called `A/B` from `A` > `B`. Older builds are read as before: the parts are taken from `folderPath`. This is a minor addition to the contract (1.1).
- Layouts and themes are linked in `references.json` and `backlinks.json`. A layout has a `usesTheme` reference to its theme, and a custom theme has a `derivedFrom` reference to the theme it was made from, so a theme's "Used By" lists its layouts and the custom themes built on it. A custom theme's base is linked only when the base is in the file (FileMaker exports a built-in theme only when a layout uses it). Contract version 1.1: two new `relationshipType` values; the schemas moved to `docs/contract/schema-1.1/`.
- Markdown: a layout or script in a folder has a breadcrumb under its title (`Scripts › Utils › Old › Name`) that links to each folder's section in the index. The Layouts and Scripts indexes are grouped by folder when any exist: a contents list, then a heading per folder (`## Utils`, `### Utils › Old`), unfiled items first. A solution without folders keeps its flat index.
- The HTML viewer's sidebar nests layouts in their folders too (scripts already were), using the folders' real names. The pages carry a `folder:` line in their front matter for this.
- WebMCP: layouts and scripts have `folderPathParts`, script steps have `scriptFolderParts`, and layout objects have `layoutFolder` and `layoutFolderParts`. A new `inFolder` op for `where` matches a folder and everything below it: `{field:"folderPathParts", op:"inFolder", value:"Utils/Old"}` (a list of names or `A › B` also work). Result lines for layouts and scripts show the folder.
- WebMCP `query_entities` takes a `types` argument (several entity types) and, with neither `type` nor `types`, searches every type, so "everything changed since a date" is one call and one results link. A type that lacks a field named in `where` is skipped and listed in `skippedTypes` (with a caveat on the results page); a field no type has is still an error listing the valid fields. A new `sort` argument (`{field, desc}`) orders matches before `limit` applies. The viewer's catalogs now list every field of each type, so skipped types are never loaded. The `#/agents` page has a "changed in the past 30 days" example.
- `build --progress rich|plain|json`. `plain` prints one line per stage and per file (`[3/12] Analyzing Invoices (4.2s)`); `json` prints one JSON object per line (`event`, `stage`, `file`, `index`, `total`, `elapsed`, and `seconds` when a file or stage ends), for tools that show a build's progress. Without the flag, a terminal still gets the Rich bars, and a pipe or file now gets `plain` lines instead of the bars' final state. The fields are in the README, under "Progress in scripts and pipes".
- `build --progress` reports two more stages, after `write_pages`: `write_viewer` (Writing HTML viewer, with `--html` or `--webmcp`) and `check` (Checking redactions: the scrubbing guard, when scrubbing is on). On a large solution they took minutes with no sign of life. Each has a Rich bar with its pages or files.
- `--progress json` and `plain` report how far a stage that counts pages or files has got (`write_pages`, `write_viewer`, `check`): a `stage_progress` event with `done`, `units` and `unit`, at most once a second in `json` and every 5 seconds in `plain` (`Writing HTML viewer: 5300/21193 pages (40.1s)`). Their `stage_done` also carries `done` and `unit`.

### Changed

- The coverage report checks six more things: layout themes, layouts left out of the Layouts menu, hide conditions that also apply in Find mode, layouts and scripts in folders, and custom privilege lists that allow creating new layouts, value lists or scripts.
- The Scripts index's second column is now the step count; it used to repeat the folder, which the folder headings now show.
- `fm-saxml serve`, and `--serve` on `build`/`render`, now use port **8766** by default instead of 8765. The agentic-fm companion server also defaults to 8765, so the two used to clash. To keep the old port, pass `--port 8765`. As before, if the port is taken, a free one is used.
- The scrubbing guard now checks a build's docs *before* they replace the previous ones. When it fails, the previous docs are kept and the rejected ones are left in `<folder>.tmp-<pid>`. Its message groups the leaks by value, and says when a value is also an object's name.
- Scrub engine version 6: a `model.json` saved by an earlier version is scrubbed again when rendered.
- The HTML viewer (`--html`, `--webmcp`) now ships its Markdown renderer instead of loading it from esm.sh and jsDelivr. It's written to `_viewer/vendor/` (about 1.7 MB, with the third-party licence notices) and works offline, from disk or from `fm-saxml serve`. Before, an outage at esm.sh broke every viewer that didn't have a cached copy. Code blocks other than ` ```filemaker ` calculations are no longer syntax-highlighted; the docs don't write any. The scrubbing guard skips `_viewer/vendor/`. The bundle is built from `viewer-vendor/` in the repository (see its README).

### Fixed

- `raw/layouts.json` kept FileMaker's record of an icon's original file name (the `FNAM` stream, encoded so the scrubber couldn't read it, sometimes a full path with a user name) for icons stored on the object (FileMaker 22 exports). It is now removed. Pictures stored on layout objects (a graphic, a PNG icon) are left out of it too unless `build --layout-images` is given; SVG button icons are kept.
- `fm-saxml serve` could refuse connections on Windows when the viewer loaded many files at once (the layout tools load up to 16 layouts together), so a tool call failed with "Could not load …". Its connection queue is longer now.
- The HTML viewer has an empty inline favicon, so a browser no longer asks `fm-saxml serve` for `/favicon.ico` and logs a 404 on every first load.

- Two script steps that share a UUID (a step copied within a script can keep it) showed the same FileMaker text: the later step's text was printed for both. Each step's text is now found by its `hash`. Calculations that share a ChunkList key the same way (copied steps, or an object's Hide condition and its "can enter" calc) no longer take each other's field and custom function references; the one FileMaker didn't write a ChunkList for is read from its text instead (`chunkRefs: null`).
- "Prohibit modification of value during data entry" was dropped from fields that have no other auto-enter option (`<AutoEnter type="" prohibitModification="True"/>`).
- Coverage report: layout `width`, `GridStyle`, `ClientType` and `Options`, and a layout object's `Options` and `LocalCSS` (its style's name), were listed under "left out on purpose" although the converter now reads them.
- Layout pages say whether the layout is included in the Layouts menu ("Include in menu"), as script pages already did.
- If an export holds a layout folder's layouts as child elements (rather than as siblings), those layouts were left out of the docs, and layouts under a `Folder`, `Group` or `LayoutFolder` wrapper were filed at the top level. Both are now read with their folders.- A script folder whose name contains `/` is one folder in the file paths, not two.
- Windows: `fm-saxml serve` and `--serve` could start on a port another server was already listening on, instead of moving to a free one, so either server might answer. The port is now bound exclusively on Windows.
- A `<Function Missing>` argument that names an object in the solution, such as `<Function Missing> ( "SlidingDrawer" )` inside the custom function SlidingDrawer, is no longer redacted as a secret. The redaction could never be complete, since names are never rewritten, so the guard stopped the build (exit 2). Such values are now listed under "Needs review". This holds across files in a multi-file build, and for the strict level's high-entropy rule and comment prose too. Rules with real evidence (a password parameter, a Crypt key, a `$password = "…"` assignment) still redact, and still stop the build if the value is also a name.
- `<Function Missing>` arguments that are MIME types, plain HTTP headers (`Content-Type: …`), plugin commands (`SMTP-SetBody`), on/off or numeric options (`ssl=true`) and mode keywords (`html`) are no longer redacted.
- Windows: a rebuild could fail with `[WinError 5] Access is denied` while moving the new docs into place, when antivirus or the search indexer was still reading the freshly written files. It left the docs folder missing, with `.old-<pid>` and `.tmp-<pid>` folders behind. Both renames of the swap now retry for about 30 seconds. If the second rename still fails, the previous docs are moved back and the message names the folder that holds the new ones.
- Windows: a rebuild failed with `Could not replace <docs>: Access is denied` when a program was using the docs folder as its current folder (a terminal or File Explorer window in it), since Windows won't rename that folder. The folder now stays and its contents are replaced instead. If something inside is held open too, everything is put back as it was, and the message names the file or folder that is in use and the usual causes.
